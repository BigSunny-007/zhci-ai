# 智策 AI

智策 AI 是面向中国投资者的多用户 AI 投研辅助 SaaS。系统聚合行情、资金流、新闻、大盘与个人持仓，生成可追溯、可评估、带风险依据的辅助判断，不执行交易，也不承诺收益。

当前版本：`v48.0.0`

## 项目结构

- `frontend/`：React + TypeScript 桌面端行情工作台。
- `backend/`：FastAPI、MySQL 数据模型、免费数据源适配器与建议引擎。
- `docker-compose.yml`：MySQL、Redis、API 与 Web 的本地部署编排。

## 风险声明

本项目输出仅用于信息整理和投研辅助，不构成任何投资建议。金融市场存在本金损失风险，任何决策都应由用户独立作出。

## v1.0.0 验证结果

- 前端：React 19 + TypeScript + Vite 7，桌面优先中文工作台已实现自选切换、搜索新增、AI 研判提示和响应式收窄布局。
- 后端：FastAPI + SQLAlchemy Async，完成邮箱认证、JWT、持仓、自选股、行情、历史、新闻和建议接口。
- 数据：内置 `demo` 免费演示 Provider；Provider 协议可替换为正式数据服务，API 响应包含来源与时间戳。
- AI：规则化证据模型以资金流 45%、价格动量 35%、权威度加权新闻 20% 生成保守观察结论，并显式列出限制条件。
- 数据库：MySQL 8.4 初始化脚本覆盖用户、持仓、自选、行情、新闻、AI 建议和审计日志。
- 通过测试：后端 `2 passed`；前端 `1 passed`；前端生产构建成功；后端 Ruff 检查通过；应用导入检查成功（8 routes）。
- 已知边界：当前演示数据不代表真实行情；未接入邮箱发送、真实数据再分发授权、生产 AI 模型、交易日调度和管理员页面，均已预留扩展位置。

### v1.0.0

### v2.0.0

基于 Koyfin 的“组合分析”定位与 Sharesight 的“多持仓绩效上下文”公开产品研究，本版本将工作台从“看行情”升级为“看结果”：新增组合相对基准表现、最大回撤、盈亏比、胜率和 AI 建议兑现率的统一分析契约，并在右侧工作台展示复盘卡片。后端新增 `/api/v1/analytics/overview`，MySQL 结构兼容后续接入真实交易流水；所有演示指标显式标记数据状态，不冒充真实收益。

验证结果：后端 `3 passed`、Ruff 检查通过；前端 TypeScript 生产构建成功、Vitest `1 passed`。本版本未改变认证和行情 API 的兼容性。

### v3.0.0

基于 TradingView 公开帮助文档中“条件、频率、有效期、消息和通知渠道”提醒对象的设计，本版本新增可审计提醒模型和 API：支持价格/涨跌幅/资金流阈值、一次/每小时/每日频率、失效时间、站内/邮箱渠道字段，并以唯一规则避免重复订阅。MySQL 增加 `alerts` 表，提醒参数在创建时冻结，便于后续评估信号是否触发以及回溯当时依据。

验证结果：后端 `5 passed`、Ruff 检查通过、应用导入检查成功（10 routes）；前端 TypeScript 生产构建成功、Vitest `1 passed`。提醒只产生通知，不执行下单。

### v4.0.0

本版本以企业 SaaS 的账号安全为主题，参考 Auth0 等成熟身份系统的“短时一次性验证、验证状态门禁和会话失效”实践，补齐邮箱验证闭环：注册生成 15 分钟有效的随机令牌，仅将 SHA-256 哈希写入 MySQL；验证成功后立即清空令牌，过期或重复使用均拒绝。开发环境响应中可选择性返回原始令牌，生产环境默认不返回，邮件发送由配置与后续 SMTP/事务邮件 Provider 接入。

认证 API 新增 `/auth/verify-email`、`/auth/resend-verification`、`/auth/refresh` 和 `/auth/logout`。未完成验证的用户不能登录或访问业务接口；JWT 携带 `session_version`，退出登录会递增版本并使该用户的历史会话立即失效。注册、成功/失败登录、令牌刷新、验证和退出均写入 `audit_logs`，不记录密码或原始验证令牌。

数据库新增 `email_verified`、`verification_token_hash`、`verification_expires_at`、`session_version` 字段，并提供可重复执行的 `backend/sql/002_email_verification.sql` 增量脚本。生产部署需配置强随机 `SECRET_KEY`、邮件服务 Provider，并将 `EXPOSE_VERIFICATION_TOKEN=false` 保持关闭。

验证结果：后端 `8 passed`、Ruff 检查通过、FastAPI 导入检查成功；前端验证将在本版本后续 UI 接入时一并覆盖。认证接口仍不执行交易，令牌刷新只轮换凭证，不改变投资数据。

### v5.0.0

本版本把“只在开盘时生成建议”从产品约定升级为可测试的交易日历护栏。调研依据为上海证券交易所官方 Trading Hours 页面（`https://english.sse.com.cn/start/trading/schedule/`），系统按产品统一口径使用 `9:30–11:30`、`13:00–15:00`，并为后续接入交易所节假日数据保留 holidays 参数。周末与配置的节假日自动标记为休市，不会误触发建议。

新增 `backend/app/core/trading_calendar.py`，统一提供时区转换、交易日判断、上午/下午/休市状态和整点建议槽位。当前建议槽位是 `10:00`、`11:00`、`14:00`（北京时间）；`/api/v1/market/session` 无需登录即可返回当前交易状态、是否允许生成建议、下一次建议时间和数据时间戳，调度器与前端共用同一契约，避免各自实现产生偏差。集合竞价与不同品种的特殊收盘规则由后续数据源适配层负责覆盖。

验证结果：后端 `11 passed`、Ruff 检查通过，OpenAPI 路由包含新的市场会话接口；前端 TypeScript 生产构建成功、Vitest `1 passed`。该护栏只控制分析建议生成，不执行交易或发出下单请求。

### v6.0.0

本版本落实“每一条 AI 建议都要留档”的数据闭环。行情建议接口现在将生成结果、完整证据快照、模型版本、置信度、建议仓位和生成时间写入 `ai_recommendations`，并新增 `/api/v1/market/recommendations` 查询当前用户的历史建议，预留 `evaluated_at` 与 `realized_return` 字段供后续兑现评估使用。

为避免刷新页面或重复轮询污染命中率，同一用户、股票、投资周期在同一 UTC 小时内采用幂等写入：已有记录直接返回，不创建重复样本。历史结果严格按用户隔离，沿用邮箱验证与 JWT 会话门禁；接口不会写入密码、令牌或任何自动交易指令。

验证结果：后端 `12 passed`、Ruff 检查通过，OpenAPI 同时包含建议生成与历史读取契约；前端 TypeScript 生产构建成功、Vitest `1 passed`。下一轮可在该留档基础上接入真实评估任务，计算建议命中率、最大回撤和不同市场阶段表现。

### v7.0.0

本版本将建议“留档”推进为“可兑现评估”。评估口径参考 QuantConnect 公开回测结果术语：只使用建议生成时保存的入场价与到期后的行情价，避免把未来数据泄漏到信号生成阶段；`1d`、`1-2d`、`1-5d`、中长期分别设置成熟等待窗口。买入观察按价格收益计算，减仓观察按反向收益计算，持有观察按持有期间收益计算。

新增 `backend/app/services/evaluation.py`，统一计算建议成熟度、方向性收益、命中率、最大回撤、盈亏比和累计收益序列。新增 `/api/v1/analytics/recommendations`，按当前用户读取最多 200 条建议；到期记录才会写入 `evaluated_at`、`realized_return` 和退出价证据，未到期记录保持待评估状态。评估结果严格隔离用户，并显式返回数据状态，演示 Provider 的结果仅用于验证链路。

验证结果：后端 `15 passed`、Ruff 检查通过，OpenAPI 包含建议评估接口；前端 TypeScript 生产构建成功、Vitest `1 passed`。该版本仍不构成投资建议、不自动交易，真实收益统计必须在获得合规授权的历史/实时数据后重新核验。

### v8.0.0

本版本建设企业 SaaS 管理后台的第一块安全基座。调研参考 OWASP Authorization Cheat Sheet 的“最小权限（Least Privilege）”与“默认拒绝（Deny by Default）”原则，新增 `admin_user` 依赖：只有已验证、有效且 `is_admin=true` 的账号可以访问管理员接口，普通用户统一返回 403。

新增 `/api/v1/admin/overview`，仅返回匿名聚合指标：用户总数/活跃数/验证数、拥有持仓的用户数、用户自报持仓成本基数、建议总量与已评估量、24 小时成功登录事件数、24 小时行情净流入。响应不包含邮箱、用户 ID、单用户持仓、IP 或可还原的资金轨迹；行情资金流仍明确受 Provider 覆盖范围限制。

验证结果：后端 `17 passed`、Ruff 检查通过，OpenAPI 管理接口仅声明 `HTTPBearer` 安全要求；前端 TypeScript 生产构建成功、Vitest `1 passed`。管理员聚合数据只用于平台运营与质量监控，不用于个体投资决策。

### v9.0.0

本版本把免费数据源从“协议预留”推进为“可选运行时适配”。调研参考 AKShare 官方文档（`https://akshare.akfamily.xyz/`）的 A 股现货、历史和个股新闻接口；由于 AKShare 依赖上游公开接口，系统将它放在 `market` 可选依赖中，不在基础安装时强制联网或安装。

新增无需登录的 `/api/v1/market/providers`，返回当前配置、可用性、来源说明和限制列表，便于管理员在配置切换后确认实际生效的数据源。Provider 目录同时保留 `demo` 与 `akshare`，后续商业源只需实现同一协议并注册即可。

验证结果：后端 `20 passed`、Ruff 检查通过，OpenAPI 包含 Provider 目录接口；前端 TypeScript 生产构建成功、Vitest `1 passed`。AKShare 上游限流、授权和字段变更仍需在生产环境配置监控与合规审查，演示数据不代表真实行情。

### v10.0.0

本版本将交易时段护栏接成可运行的后台任务。调研依据为 APScheduler 官方 `AsyncIOScheduler` 与 `CronTrigger` 文档（`https://apscheduler.readthedocs.io/en/3.x/modules/schedulers/asyncio.html`、`https://apscheduler.readthedocs.io/en/3.x/modules/triggers/cron.html`）：使用 asyncio 调度器、显式 `Asia/Shanghai` 时区、工作日 Cron 触发器，并设置 `max_instances=1`、`coalesce=true`、5 分钟误触发宽限。

新增 `backend/app/services/scheduler.py`。当 `ENABLE_SCHEDULER=true` 时，FastAPI 生命周期启动 `10:00`、`11:00`、`14:00` 建议周期任务；任务只处理有效且已验证用户的自选/持仓标的，调用当前 Provider 生成建议，并复用 v6 的小时幂等规则。每次运行写入 `audit_logs`，记录生成、跳过、失败数量与实际 Provider；任务异常按标的隔离，不会中断整轮任务。管理员可通过 `/api/v1/admin/scheduler` 查看启用状态、运行状态、时区和下一次运行时间。

默认仍关闭调度，开发环境不会自动联网或写入建议。生产部署必须只启用一个调度进程（API 多副本时将调度器拆为独立 Worker），并配置真实数据源、节假日覆盖和告警；当前任务不执行交易。

验证结果：后端 `22 passed`、Ruff 检查通过，OpenAPI 包含管理员调度状态接口；前端 TypeScript 生产构建成功、Vitest `1 passed`。调度器只负责生成分析样本，收益与风险结论仍需经过 v7 评估链路和人工复核。

### v11.0.0

本版本补齐认证接口的暴力尝试防护。调研依据为 OWASP Authentication Cheat Sheet 与 Authorization Cheat Sheet（`https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html`、`https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html`）中关于认证失败保护、最小权限和默认拒绝的建议。

新增 `backend/app/services/rate_limit.py` 的线程安全滑动窗口限流器，并应用于 `/auth` 全部接口：默认按“客户端地址 + 路径”每分钟最多 20 次，超限返回 `429` 与 `Retry-After`，窗口自动清理，避免内存无限增长。通过 `RATE_LIMIT_ENABLED` 和 `AUTH_RATE_LIMIT_PER_MINUTE` 可配置，便于不同 SaaS 套餐和部署环境调整。

限流存储抽象保持在服务层，当前默认是进程内实现，适合单实例开发和基础保护；生产多副本必须将同一契约替换为 Redis/网关共享限流，并结合 WAF、设备指纹和告警策略，不能把进程内计数当作完整的分布式防护。限流不记录密码、令牌或请求正文。

验证结果：后端 `24 passed`、Ruff 检查通过，OpenAPI 认证路由保持完整；前端 TypeScript 生产构建成功、Vitest `1 passed`。限流只防护认证滥用，不改变邮箱验证、会话失效和行情建议逻辑。

### v12.0.0

本版本补齐个人账号的数据可携带与退出机制，设计依据为《中华人民共和国个人信息保护法》中关于个人查阅、复制、更正、删除个人信息的原则；具体生产上线仍需经过法务对数据分类、保存期限和监管例外进行复核，不以本版本接口替代法律意见。

新增 `/api/v1/auth/data-export`，导出当前账号的基本资料、持仓、自选股、已留档建议和个人审计事件；响应明确不包含密码哈希、验证令牌或管理员聚合数据。新增 `/api/v1/auth/delete-account`，要求已登录账号再次提交密码和固定确认短语 `DELETE_ACCOUNT`，先写入去标识化的删除审计事件，再显式删除持仓、自选、建议、提醒和用户记录，避免依赖数据库级联差异。

导出与注销沿用邮箱验证、JWT 会话版本和认证限流，所有数据查询按当前用户隔离。删除接口不会删除平台必要的审计记录，数据库外键将操作者标识置空；接口不执行交易，也不影响其他用户或匿名聚合指标的结构。

验证结果：后端 `26 passed`、Ruff 检查通过，OpenAPI 包含导出与注销契约；前端 TypeScript 生产构建成功、Vitest `1 passed`。生产环境启用前必须补充数据保留策略、异步导出大文件存储、工单审批和法务审查。

### v13.0.0

本版本落实“系统可提出优化，但规则和权重变更必须人工确认”的治理边界。调研参考 NIST AI Risk Management Framework（`https://www.nist.gov/itl/ai-risk-management-framework`）关于 Govern、Measure、Manage 和可信 AI 风险管理的公开框架：策略必须具备明确版本、责任人、审核时间和可追溯证据，运行中的模型不能被无审批地静默替换。

新增 `ai_model_policies` 表、`PolicyWeights` 权重契约和 `AIModelPolicy` 状态模型。策略只能按 `draft → pending_review → active → retired` 顺序流转；权重必须严格求和为 1，版本号和理由均需通过校验。管理员新增 `/api/v1/admin/model-policies` 列表/创建接口，以及 `/{policy_id}/{action}` 提交审核、激活、退役接口；每次状态变化写入 `audit_logs`，激活新策略会先退役旧 active 策略。

建议接口和后台调度器都会读取当前 active 策略，并把策略版本、实际权重和评分快照写入每条建议的 `evidence` 与 `model_version`。没有 active 策略时继续使用并明确标记 `rule-based-v1` 默认权重；不存在自动调参、自动激活或自动下单路径。该设计允许系统后续生成优化草稿，但上线前必须由管理员显式审核。

验证结果：后端 `30 passed`、Ruff 检查通过，OpenAPI 包含策略管理接口；前端 TypeScript 生产构建成功、Vitest `1 passed`。生产环境还需补充双人审批、策略差异审阅、灰度发布和回滚演练，当前版本不构成投资建议。

### v14.0.0

本版本将策略治理从单管理员确认升级为职责分离的双人审批。设计依据为 NIST AI Risk Management Framework 的 Govern、Measure、Manage 组织治理原则：模型规则需要明确责任人、独立复核和可追溯证据，系统不能因单个操作者的动作而静默改变运行策略。

`ai_model_policies` 新增 `review_round`；新增 `ai_model_policy_approvals` 审批记录表，按策略和审批轮次记录审批人、同意/驳回决定、意见与时间。策略提交后进入 `pending_review`，至少两名不同管理员在同一轮次同意才会激活；同一管理员重复审批会被拒绝，任一管理员可驳回并退回草稿，重新提交会开启新的审批轮次。创建者可以参与审批，但不能单独完成激活。

管理员策略接口支持可选审批意见，并新增 `GET /api/v1/admin/model-policies/{policy_id}/approvals` 查看完整审批历史；状态变化和审批数量继续写入 `audit_logs`。激活时仍自动退役旧策略，但不存在自动审批、自动激活或自动下单路径。

### v46.0.0

本版本统一总览和持仓页面的组合估值来源。调研投资 SaaS 的首页可信度后，发现顶部仍显示演示资产与收益，而持仓页已能展示 Provider 估值，前后页面不一致会造成严重误读。

总览主卡现在调用 `getPortfolioSummary`，登录后显示组合市值、未实现盈亏、估值时间和数据源状态，并隐藏无法证明来源的演示曲线；未登录时保留明确的演示标识。估值接口仍按用户隔离并报告覆盖数量，不把浮盈亏标注为“今日收益”。

### v47.0.0

本版本补齐个人数据权利工作流。调研企业 SaaS 的可携带性和隐私要求后，发现后端虽已提供数据导出接口，但用户无法从界面下载自己的投研记录；导出必须明确账号范围，并且不能把演示数据混入个人文件。

新增 `DataExportPanel` 和 `getDataExport` 客户端方法，登录用户可下载包含个人资料、持仓、自选、建议和审计事件的 JSON 文件；未登录时按钮禁用并显示说明，下载失败时保留可重试状态。服务端既有用户隔离、导出上限和敏感字段边界保持不变。

新增数据导出客户端回归测试并校验 OpenAPI 路由；前端 `5` 个测试文件、`19` 个测试通过并完成生产构建，后端 `38 passed`、Ruff 检查通过。本版本不提供他人数据访问、不删除审计记录；生产环境应增加导出任务审计、加密存储、下载链接短时效和导出频率限制。

### v48.0.0

本版本增加市场 API 的 Provider 保护。调研免费行情源的频率限制和多租户 SaaS 稳定性后，发现行情、新闻和建议接口没有统一请求护栏，单个客户端可能耗尽上游配额并影响其他用户。

新增可配置 `MARKET_RATE_LIMIT_PER_MINUTE`（默认每个客户端、每条市场路径每分钟 `120` 次）的滑动窗口限流，超限返回 `429` 和 `Retry-After`；认证限流与市场限流使用独立命名空间。该保护只限制请求频率，不改变交易日历、建议槽位或任何投资逻辑。

新增市场限流命名空间回归测试；前端 `5` 个测试文件、`19` 个测试通过并完成生产构建，后端 `39 passed`、Ruff 检查通过。本版本不宣称 Provider 配额已获得；生产环境应使用 Redis 分布式计数、按租户配额、来源 SLA 和上游 `429` 监控替换进程内限流。

新增总览估值接入回归；前端 `5` 个测试文件、`18` 个测试通过并完成生产构建，后端 `38 passed`、Ruff 检查通过。本版本不声称账户余额或实时收益，生产环境应继续接入券商流水、行情缓存和估值审计快照。
